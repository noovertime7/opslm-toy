计算机网络允许不同设备之间交换数据。

IP 地址用于标识网络中的设备。

IPv4 地址长度为 32 位。

IPv6 地址长度为 128 位。

子网掩码用于划分网络部分和主机部分。

默认网关用于访问本地网络之外的设备。

路由表决定数据包应该通过哪个网络接口或者网关发送。

TCP 是一种面向连接的可靠传输协议。

TCP 建立连接通常需要三次握手。

TCP 关闭连接通常涉及四次挥手。

TCP 会通过序列号和确认机制保证数据可靠传输。

TCP 重传通常说明网络出现丢包、拥塞或者对端响应异常。

UDP 不需要建立连接。

DNS 负责将域名解析成 IP 地址。

DNS 故障可能表现为域名无法解析，但直接访问 IP 地址正常。

HTTP 是常见的应用层协议。

HTTPS 在 HTTP 基础上使用 TLS 提供加密通信。

HTTP 502 通常表示网关从上游服务获得了无效响应。

HTTP 503 通常表示服务暂时不可用。

HTTP 504 通常表示网关等待上游服务响应超时。

排查网络问题时应该逐层缩小范围。

首先可以检查本机网络接口是否正常。

然后检查路由。

然后检查 DNS。

然后检查端口连通性。

最后再检查应用层协议。

ss -lntp 可以查看正在监听的 TCP 端口。

curl 可以观察 HTTP 请求的响应状态。

tcpdump 可以抓取网络数据包。

抓包可以帮助分析 TCP 重传、连接建立和协议交互过程。

iptables 和 nftables 都可以用于配置 Linux 防火墙。

防火墙规则配置错误可能导致服务无法访问。

负载均衡器可以将请求分发到多个后端服务。

网络故障排查应该避免只根据 ping 的结果判断所有网络功能是否正常。
