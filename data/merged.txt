计算机是一种能够按照程序执行计算和信息处理的设备。

操作系统负责管理计算机的处理器、内存、磁盘、网络和其他硬件资源。

现代软件系统通常由多个组件组成，不同组件之间通过网络或者本地接口进行通信。

程序运行时需要使用 CPU、内存、磁盘和网络等系统资源。

服务器是一种长期运行并向其他设备提供服务的计算机。

客户端通常通过网络访问服务器提供的服务。

互联网中的设备通过 IP 地址进行寻址。

域名系统 DNS 可以把域名转换成 IP 地址。

TCP 是一种面向连接的传输协议，可以提供可靠的数据传输。

UDP 是一种无连接的传输协议，通常用于对实时性要求较高的场景。

软件开发通常包括需求分析、设计、开发、测试、发布和维护等阶段。

日志是软件系统记录运行状态和事件的重要方式。

监控系统可以持续采集服务器和应用程序的运行指标。

告警系统通常根据监控指标、日志或者事件触发通知。

分布式系统由多个独立节点共同完成计算任务。

在分布式系统中，网络延迟、节点故障和数据一致性都是重要问题。

数据库用于存储和管理结构化数据。

缓存可以减少对后端数据库的访问，提高系统性能。

消息队列可以在不同服务之间进行异步通信。

高可用系统通常需要避免单点故障。

负载均衡可以把请求分发到多个后端实例。

服务发现可以帮助应用找到其他服务的网络地址。

自动化是运维工作的核心能力之一。

基础设施即代码可以通过代码描述服务器、网络和其他基础设施资源。

持续集成和持续交付可以帮助团队更快地发布软件。

当系统发生故障时，工程师通常需要先确认现象，然后收集证据，再分析原因。

故障排查应该尽量避免依赖猜测，而应该通过日志、指标和系统状态进行验证。

生产环境中的操作需要特别谨慎。

高风险操作应该提前确认影响范围，并准备回滚方案。

系统性能问题可能来自 CPU、内存、磁盘、网络、应用程序或者外部依赖。

一个好的故障排查过程通常从现象开始，逐步缩小问题范围。
Linux 是一种广泛使用的开源操作系统。

Linux 内核负责进程调度、内存管理、文件系统、设备驱动和网络协议栈。

Linux 中的进程是正在运行的程序实例。

每个进程通常拥有一个唯一的进程 ID，也就是 PID。

ps 命令可以查看系统中的进程。

top 命令可以实时观察系统负载和进程资源使用情况。

htop 提供了更加直观的进程监控界面。

uptime 可以查看系统运行时间和平均负载。

load average 可以帮助判断系统当前的负载情况。

free 命令可以查看系统内存使用情况。

Linux 会使用空闲内存作为文件缓存。

因此不能简单根据 free 输出中的 used 数值判断系统是否缺少内存。

available 通常比 free 更适合判断当前还有多少可用内存。

vmstat 可以观察 CPU、内存、进程和 IO 等系统指标。

mpstat 可以查看 CPU 使用情况。

pidstat 可以观察不同进程的 CPU、内存和 IO 使用情况。

iostat 可以用于分析磁盘 IO 性能。

磁盘 IO 问题通常需要关注吞吐量、IOPS、延迟和队列长度。

df 命令用于查看文件系统的磁盘空间使用情况。

du 命令可以统计目录和文件占用的空间。

如果磁盘空间耗尽，应用程序可能无法继续写入日志或数据。

inode 耗尽也可能导致无法创建新的文件。

df -i 可以查看文件系统 inode 的使用情况。

Linux 中的文件权限通常由用户、用户组和其他用户三个部分组成。

chmod 可以修改文件权限。

chown 可以修改文件的所有者和所属用户组。

systemd 是现代 Linux 系统中常见的服务管理器。

systemctl status 可以查看服务状态。

systemctl start 可以启动服务。

systemctl stop 可以停止服务。

systemctl restart 可以重新启动服务。

journalctl 可以查看 systemd 管理服务产生的日志。

journalctl -u 可以查看指定服务的日志。

dmesg 可以查看内核日志。

Linux 中的 OOM Killer 会在系统严重缺少内存时终止部分进程。

如果容器或者进程因为内存不足被终止，应该进一步检查内存限制和实际内存使用情况。

kill 可以向进程发送信号。

SIGTERM 通常用于请求进程正常退出。

SIGKILL 会直接终止进程，进程无法捕获该信号。

使用 kill -9 之前应该确认普通终止方式是否无效。

lsof 可以查看进程打开的文件和网络连接。

ss 可以查看 TCP 和 UDP socket。

ip addr 可以查看网络接口和 IP 地址。

ip route 可以查看系统路由表。

ping 可以用于测试基本网络连通性。

traceroute 可以帮助观察网络路径。

curl 可以用于测试 HTTP 服务。

dig 可以用于查询 DNS。

nslookup 也可以进行 DNS 查询。

Linux 故障排查不应该一开始就重启服务器。

通常应该先收集当前状态、日志和监控指标，避免丢失重要现场信息。
Kubernetes 是一个用于自动部署、扩缩容和管理容器化应用的平台。

Kubernetes 集群通常由控制平面节点和工作节点组成。

Pod 是 Kubernetes 中最小的可调度单位。

一个 Pod 可以运行一个或者多个容器。

Deployment 用于管理无状态应用。

StatefulSet 通常用于管理有状态应用。

DaemonSet 可以确保指定节点上运行一个 Pod。

Service 可以为一组 Pod 提供稳定的访问入口。

ClusterIP 是 Kubernetes Service 的默认类型。

NodePort 可以通过节点端口暴露服务。

LoadBalancer 通常用于与云平台负载均衡器结合。

Ingress 可以根据域名和路径转发 HTTP 请求。

ConfigMap 可以保存非敏感配置。

Secret 通常用于保存密码、令牌和证书等敏感数据。

Namespace 可以用于对 Kubernetes 资源进行逻辑隔离。

kubectl get pods 可以查看 Pod。

kubectl get pods -A 可以查看所有 Namespace 中的 Pod。

kubectl describe pod 可以查看 Pod 的详细信息和事件。

kubectl logs 可以查看容器日志。

kubectl exec 可以进入容器执行命令。

Pod 处于 Pending 状态时，可能是因为资源不足、调度限制或者存储问题。

Pod 出现 CrashLoopBackOff 时，通常表示容器启动后不断退出并重新启动。

排查 CrashLoopBackOff 时应该先查看容器日志和 Pod Events。

OOMKilled 通常表示容器超过了内存限制或者节点出现严重内存压力。

ImagePullBackOff 通常和镜像地址、认证信息或者网络问题有关。

Kubernetes Scheduler 负责为尚未调度的 Pod 选择合适的节点。

Scheduler 会综合考虑资源请求、亲和性、污点和容忍等调度条件。

requests 用于告诉 Kubernetes 一个容器期望使用多少资源。

limits 用于限制容器最多可以使用多少资源。

如果 CPU limit 设置过低，容器可能出现 CPU throttling。

如果 memory limit 设置过低，容器可能因为 OOM 被终止。

Liveness Probe 用于检查容器是否仍然健康。

Readiness Probe 用于判断 Pod 是否可以接收流量。

Startup Probe 可以用于启动时间较长的应用。

Kubernetes 中的 PersistentVolume 用于描述持久化存储资源。

PersistentVolumeClaim 是用户对存储资源的申请。

CSI 是 Kubernetes 中用于集成存储系统的标准接口。

CNI 是 Kubernetes 中用于实现容器网络的标准接口。

生产环境中修改 Kubernetes 资源之前应该确认变更影响范围。

遇到 Kubernetes 故障时，应该结合 Pod 状态、Events、日志、节点状态和监控指标进行分析。
计算机网络允许不同设备之间交换数据。

IP 地址用于标识网络中的设备。

IPv4 地址长度为 32 位。

IPv6 地址长度为 128 位。

子网掩码用于划分网络部分和主机部分。

默认网关用于访问本地网络之外的设备。

路由表决定数据包应该通过哪个网络接口或者网关发送。

TCP 是一种面向连接的可靠传输协议。

TCP 建立连接通常需要三次握手。

TCP 关闭连接通常涉及四次挥手。

TCP 会通过序列号和确认机制保证数据可靠传输。

TCP 重传通常说明网络出现丢包、拥塞或者对端响应异常。

UDP 不需要建立连接。

DNS 负责将域名解析成 IP 地址。

DNS 故障可能表现为域名无法解析，但直接访问 IP 地址正常。

HTTP 是常见的应用层协议。

HTTPS 在 HTTP 基础上使用 TLS 提供加密通信。

HTTP 502 通常表示网关从上游服务获得了无效响应。

HTTP 503 通常表示服务暂时不可用。

HTTP 504 通常表示网关等待上游服务响应超时。

排查网络问题时应该逐层缩小范围。

首先可以检查本机网络接口是否正常。

然后检查路由。

然后检查 DNS。

然后检查端口连通性。

最后再检查应用层协议。

ss -lntp 可以查看正在监听的 TCP 端口。

curl 可以观察 HTTP 请求的响应状态。

tcpdump 可以抓取网络数据包。

抓包可以帮助分析 TCP 重传、连接建立和协议交互过程。

iptables 和 nftables 都可以用于配置 Linux 防火墙。

防火墙规则配置错误可能导致服务无法访问。

负载均衡器可以将请求分发到多个后端服务。

网络故障排查应该避免只根据 ping 的结果判断所有网络功能是否正常。
AI Infra 是人工智能系统背后的基础设施工程。

大模型训练通常需要大量 GPU 计算资源。

GPU 擅长执行大规模并行计算。

NVIDIA GPU 广泛用于深度学习训练和推理。

CUDA 是 NVIDIA 提供的并行计算平台。

PyTorch 可以使用 CUDA 在 NVIDIA GPU 上执行张量计算。

GPU 显存用于保存模型参数、激活值、梯度和优化器状态。

训练大型模型时，显存不足是常见问题。

减少 batch size 可以降低显存使用。

Gradient Accumulation 可以通过多次累积梯度模拟更大的 batch size。

Mixed Precision 可以降低显存使用并提高部分 GPU 上的训练速度。

FP16 和 BF16 都属于低精度浮点格式。

BF16 拥有和 FP32 相同的指数位宽，因此通常拥有更大的数值范围。

Tensor Parallel 可以把单个模型层的计算分布到多个 GPU。

Pipeline Parallel 可以把不同模型层分布到不同 GPU。

Data Parallel 会在多个 GPU 上复制模型，并处理不同的数据。

NCCL 是 NVIDIA 提供的多 GPU 通信库。

AllReduce 是分布式训练中常见的集合通信操作。

NVLink 可以提供 GPU 之间的高速互联。

PCIe 也可以用于 GPU 与 CPU 或 GPU 之间的数据传输。

RDMA 可以让不同服务器之间进行低延迟、高吞吐的数据传输。

InfiniBand 是高性能计算环境中常见的高速网络技术。

大模型推理和训练的资源需求不同。

训练阶段需要保存梯度和优化器状态。

推理阶段通常不需要保存训练梯度。

KV Cache 可以保存 Transformer 推理过程中已经计算过的 Key 和 Value。

随着上下文长度增加，KV Cache 会消耗更多显存。

vLLM 是一个面向大语言模型推理的开源系统。

Continuous Batching 可以提高推理服务的 GPU 利用率。

模型量化可以降低模型存储和显存需求。

INT8 和 INT4 是常见的量化精度。

GPU 利用率不能单独代表训练效率。

训练性能分析还需要关注显存、吞吐量、计算利用率和通信开销。

在 Kubernetes 中运行 GPU 工作负载时，需要通过设备插件让容器访问 GPU。

GPU Scheduler 可以根据 GPU 资源需求进行任务调度。

GPU 虚拟化和共享技术可以提高 GPU 资源利用率。
